# 공문 자동 작성 에이전트 설계도 v4

> v3(운영 복병 대응) → v4(경량화) 개정판
> 5단계 검증(요구사항 의심 → 제거 → 단순화 → 가속 → 자동화)을 통과한 결과:
> **도구 4→2, XSD 빌드 삭제, 검증 규칙 최소셋, "인프라 먼저"를 "실문서 1건 먼저"로 역전.**
> 새 설계 원칙: **실패 주도 성장** — 규칙·데이터·자동화는 예상이 아니라 실제 발생한 실패에서만 추가한다.

---

## 1. 확정 사항
- 환경: Windows + 한글 설치 (사람 검토 시 한글 열람 가능)
- 최종 제출 포맷: **HWPX** (.hwp 변환 요구 없음)
- MVP 성공 기준: W1(신규)·W2(회신) 각 5건을 수정 없이 발송 가능한 수준으로 생성

## 2. 아키텍처 (역할 5+1, 어댑터 2)

```
지시 / 수신 공문 / 데이터
   ▼
① Reader          [kordoc]  모든 문서 → Markdown + 구조
   ▼
② Knowledge       knowledge/ 폴더 (실문서가 쌓이며 성장)
   ▼
③ Reasoning       [LLM]  유사 사례 참조 → 초안 / 라우팅 / 확신 없으면 질문
   ▼
④ Editor          [Canine89/hwpxskill 주력]  생성·양식보존교체·템플릿
                  [kordoc patch/fill 보조]   셀·문단 단위 패치
   ▼
⑤ Validator       fix_namespaces → validate → page_guard(자기교정 2회)
                  → 최소 규칙 3종 → diff
   ▼
⑥ Human Approval  한글로 열어 확인(최종 방어선) → 검토 → 온나라 등록(수동)
```

**v3 대비 제거된 것과 이유**
| 제거 | 이유 | 부활 조건 |
|------|------|-----------|
| Editor.A (jkf87/hwpx-skill) 주력 지위 | Canine89와 역할 중복 (생성·템플릿·편집) | 실패 매트릭스의 폴백으로만 유지 (F4) |
| Editor.D (hwp-mcp) + §7 운영 규칙 전체 | HWPX 확정으로 .hwp 저장 요구 소멸. 한글 열람 검증은 사람 검토가 대체. 표 구조 변경은 재생성 우회 존재 | 표 구조 변경이 **월 수 회 이상 실제로 발생**하면 도입 재검토 |
| XSD 검증 유틸 별도 빌드 | XSD 통과 ≠ 한글에서 열림. 최종 방어선이 사람의 한글 열람이라면 불완전한 중간 검증기는 비용 | 사람 검토 없는 무인 배치(W5)를 실운영할 때 |
| 금칙어 사전·문서번호 정규식·orgs.csv 필수 준비물 | 예상 오류 대비 규칙은 대개 안 쓰임 | 해당 유형의 **실제 실패가 발생하면** 그때 추가 |

## 3. 라우팅 (4줄)
```
새 문서 / 양식 유지 교체     → Canine89 (템플릿·레퍼런스 복원)
특정 셀·문단만 수정          → kordoc patchHwpx / fillForm
표 구조 변경(행·열·병합)     → MD 추출 → 수정 → Canine89 재생성 (우회가 기본)
확신 없음                    → 사람에게 질문 (임의 진행 금지)
```
**금지 규칙 유지**: 마크다운 표만 보고 위치 추정 금지 — 플레이스홀더 또는 (row, col) 셀 주소만.

## 4. 실패 처리 매트릭스 (갱신)
공통 원칙 유지: 동일 단계 2회 실패 시 중단 + 사람 에스컬레이션. 모든 실패는 기록.

| # | 상황 | 1차 | 2차 | 폴백 |
|---|------|-----|-----|------|
| F1 | kordoc 파싱 실패 | 포맷 변환 후 재시도 | jkf87 변환기 경유 | 사람이 내용 제공 |
| F2 | 스캔 PDF | OCR | 이미지 직접 판독 | 사람 구술 |
| F3 | 필드 매핑 불일치 | 구조 재분석 → 재매핑 | 매핑표 사람 확인 | 수동 매핑 |
| F4 | validate/네임스페이스 실패 | fix_namespaces 재실행 | **jkf87/hwpx-skill로 재생성 (폴백 도구)** | 사람 검토 |
| F5 | page_guard 실패 | "문맥 유지 10% 압축" 자기교정 | 재시도 (총 2회) | diff 첨부, 사람 판단 |
| F6 | 표 구조 변경 필요 | 재생성 우회 (라우팅 기본) | — | 빈도 높으면 hwp-mcp 도입 재검토 |
| F7 | 암호화·DRM | 즉시 보고 (우회 금지) | — | 해제본 요청 |

## 5. Validator (최소셋 + 실패 주도 성장)
**고정 파이프라인**: fix_namespaces → validate → page_guard → 규칙 3종 → diff

**규칙 최소셋 (시작 시점)**
1. 날짜 형식 (`2026. 7. 7.`) — 자동 수정
2. 항목부호 8단계 순서 — 자동 수정
3. 붙임 정합 (본문 언급 수 = 실제 첨부 수) — 불일치 보고

**성장 규칙**: 사람 검토에서 같은 유형의 지적이 2회 나오면 그 검증 규칙을 추가한다. 규칙 추가의 근거는 항상 audit 로그나 검토 기록에 남은 실제 사례여야 한다.

**최종 방어선**: 발송 전 사람이 한글로 열어 확인 (Human Approval 필수 항목 — 원래 검토 절차의 일부이므로 추가 비용 없음).

## 6. 로드맵 (역전: 실문서 먼저, 인프라는 실패가 요구할 때)

**세션 1 — 관통 테스트 (인프라 없이)**
실제 공문 1건으로 파싱 → 초안 → HWPX 생성 → 한글로 열기까지 한 번에 관통한다.
훅 없이, orgs.csv 없이, 폴더 구조도 최소로. **여기서 나온 실패 목록이 진짜 요구사항이다.**

**세션 2~N — MVP (실패 주도)**
- 관통 테스트의 실패를 하나씩 해소하며 W1 5건 → W2 5건 달성
- 사람이 검토에서 고친 내용은 knowledge/examples에 환류 (회차마다 품질 상승)
- 이 과정에서 필요해진 데이터 자산(수신기관 목록 등)만 그때 만든다

**MVP 달성 후 — 자동화 승격**
- scripts/validate_pipeline.py 작성 → 휴면 중인 Stop 훅 루프 자동 활성화
- 안정화된 W1·W2 절차를 슬래시 커맨드(스킬)로 승격
- W3(양식 채우기)~W5(대량 생성) 확장, 반복 양식 플레이스홀더 태깅

## 7. 훅 (변경 없음, 활성 시점만 명확화)
- PreToolUse(보호)·PostToolUse(audit)는 세션 1부터 걸어도 무해하나 **없어도 시작 가능**
- Stop(검증 루프)은 validate_pipeline.py 생성 전까지 휴면 — 설계 그대로
- hwp-mcp 보류에 따라 protect_files.py의 taskkill 예외 처리 제거 (일괄 차단)

## 8. 자동화 한계선 (불변)
1. 온나라/전자결재 등록은 사람. 파일 완성까지가 에이전트 책임.
2. Human Approval + 한글 열람 확인 생략 금지.
3. 암호화·DRM은 즉시 보고.
