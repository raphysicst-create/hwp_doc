# HWPX 신규 작성 방법 — 다른 작업 이식용 가이드

작성: 2026. 8. 1. / 본 문서의 모든 명령은 당일 실제 실행으로 검증됨 (스모크 테스트 → validate → fix_namespaces → finalize → 한컴 COM 실열림 전부 PASS).

## 0. 핵심 개념: HWPX는 "ZIP + XML"이다

HWPX는 OWPML 표준의 XML 파일들을 ZIP으로 묶은 컨테이너다. 즉 **한글 프로그램 없이도** 텍스트 편집기와 Python만으로 신규 파일을 만들 수 있다. 유효한 최소 패키지는 파일 11개다:

```
mimetype                  # "application/hwp+zip" 19바이트. ZIP 첫 엔트리 + 무압축(STORED) 필수
version.xml               # 포맷 버전 선언
settings.xml              # 캐럿 위치 등 (최소 내용이면 됨)
META-INF/container.xml    # 패키지 진입점 선언
META-INF/container.rdf
META-INF/manifest.xml
Contents/content.hpf      # OPF 매니페스트 (파일 목록·메타데이터·spine)
Contents/header.xml       # 스타일 정의: 폰트·charPr(글자)·paraPr(문단)·borderFill(테두리)
Contents/section0.xml     # 본문. 실제 내용은 전부 여기
Preview/PrvText.txt       # 미리보기 (한글이 저장 시 재생성, 낡아도 무방)
Preview/PrvImage.png
```

본문 작성은 사실상 `section0.xml` 하나, 스타일은 `header.xml` 하나를 다루는 일이다. 나머지 9개는 "스켈레톤"으로 한 번 확보하면 재사용한다.

## 1. 이식 시 가져갈 것

| 대상 | 경로 | 비고 |
|---|---|---|
| 스크립트 일체 | `.claude/skills/hwpx/scripts/` | build/validate/finalize/page_guard/content_guard 등 |
| 템플릿 | `.claude/skills/hwpx/templates/` | base(스켈레톤) + gonmun/report/minutes/proposal 오버레이 |
| 스킬 문서 | `.claude/skills/hwpx/SKILL.md`, `references/hwpx-format.md` | 규칙·스타일 ID 맵·OWPML 레퍼런스 |

의존성: **Python 3.12+ 와 `lxml`** (필수), `python-hwpx` (C경로용, 선택), `pywin32` (한컴 COM 실열림 검사용, Windows+한글 설치 환경만).

> 주의: `templates/base/`에 `Contents/`·`META-INF/`·`Preview/`가 처음부터 누락되어 build_hwpx.py 신규 생성이 실패하던 결함이 있었고, 2026. 8. 1. python-hwpx 빈 문서 스켈레톤(validate+COM 실열림 검증 완료)으로 보수됐다. 이식할 때 base 폴더가 **11개 구성 전부**를 담고 있는지 반드시 확인할 것.

## 2. 신규 작성 경로 3가지 (전부 검증됨)

### 경로 A — build_hwpx.py + 템플릿 (표준, 권장)

base 스켈레톤 복사 → 문서 유형 오버레이(header/section0 교체) → 커스텀 XML 오버라이드 → 메타데이터 → 검증 → 패키징을 한 번에 한다.

```bash
SKILL=".claude/skills/hwpx"

# 빈 문서
python "$SKILL/scripts/build_hwpx.py" --output result.hwpx

# 공문 템플릿 + 메타데이터
python "$SKILL/scripts/build_hwpx.py" --template gonmun \
  --title "제목" --creator "기관명" --output result.hwpx

# 본문을 직접 작성한 경우 (핵심 사용법)
python "$SKILL/scripts/build_hwpx.py" --template gonmun \
  --section my_section0.xml --output result.hwpx

# 스타일까지 커스텀
python "$SKILL/scripts/build_hwpx.py" \
  --header my_header.xml --section my_section0.xml --output result.hwpx
```

템플릿: `gonmun`(공문) / `report`(보고서) / `minutes`(회의록) / `proposal`(제안서). 각각의 charPr/paraPr/borderFill ID 맵은 SKILL.md의 "템플릿별 스타일 ID 맵" 참조 — **section0.xml에서 이 ID를 참조해 서식을 입힌다.**

### 경로 B — 기증자(donor) 스켈레톤 + unpack/pack 조립 (스킬 템플릿 없이도 가능)

아무 유효한 HWPX 하나(한글에서 빈 문서를 HWPX로 저장한 것이면 충분)를 스켈레톤으로 삼는 방법. 스킬 폴더가 없는 환경에 이식할 때 가장 확실하다.

```bash
# 1) 유효한 HWPX를 디렉토리로 해체 (XML 바이트 보존 모드)
python "$SKILL/scripts/office/unpack.py" donor.hwpx ./skeleton

# 2) Contents/header.xml, Contents/section0.xml을 교체하거나 직접 편집
#    (나머지 9개 파일은 그대로 둔다)

# 3) 재패키징 — mimetype 첫 엔트리 + STORED 순서를 스크립트가 보장
python "$SKILL/scripts/office/pack.py" ./skeleton result.hwpx
```

주의: `unpack.py --pretty`로 푼 디렉토리는 절대 pack 입력으로 쓰지 않는다(pretty-print 공백이 본문 텍스트로 렌더링될 수 있음). 일반 ZIP 명령으로 재압축하지 않는다 — mimetype이 첫 엔트리·무압축이어야 한글이 연다.

### 경로 C — create_document.py (마크다운 → HWPX 초고속 경로)

`python-hwpx` 라이브러리가 내장 빈 문서 스켈레톤을 제공하므로 템플릿 없이도 즉시 생성된다. 서식 제어가 제한적이라 초안·간단 문서용.

```bash
pip install python-hwpx
python "$SKILL/scripts/create_document.py" --input content.md --output result.hwpx
# content.md: 제목(#), 문단, 파이프 표 지원
```

### (참고) 양식이 이미 있으면 신규 생성하지 말 것

기존 양식/레퍼런스 HWPX가 있으면 위 경로 대신 `hwpx_slots.py`로 슬롯 추출 → `edit_hwpx.py --slot-json`으로 구조 보존 채움이 우선이다(서식 100% 보존). 신규 생성은 **참조할 파일이 정말 없을 때**의 방법이다.

## 3. section0.xml 작성 규칙 (본문)

### 뼈대 — 첫 문단에 secPr 필수

첫 `<hp:p>`의 첫 `<hp:run>`에 반드시 `<hp:secPr>`(용지·여백)과 `<hp:colPr>`가 있어야 한다. `templates/base/Contents/section0.xml`(또는 donor의 것)의 첫 문단을 통째로 복사해 시작하는 것이 정석이다.

```xml
<?xml version='1.0' encoding='UTF-8'?>
<hs:sec xmlns:hp="http://www.hancom.co.kr/hwpml/2011/paragraph"
        xmlns:hs="http://www.hancom.co.kr/hwpml/2011/section">
  <!-- 첫 문단: secPr + colPr (base에서 복사) -->
  <hp:p id="1000000001" paraPrIDRef="0" styleIDRef="0" pageBreak="0" columnBreak="0" merged="0">
    <hp:run charPrIDRef="0">
      <hp:secPr ...>...</hp:secPr>
      <hp:ctrl><hp:colPr id="" type="NEWSPAPER" layout="LEFT" colCount="1" sameSz="1" sameGap="0"/></hp:ctrl>
    </hp:run>
    <hp:run charPrIDRef="0"><hp:t/></hp:run>
  </hp:p>
  <!-- 이후 본문 문단들 -->
  <hp:p id="1000000002" paraPrIDRef="0" styleIDRef="0" pageBreak="0" columnBreak="0" merged="0">
    <hp:run charPrIDRef="0"><hp:t>본문 내용</hp:t></hp:run>
  </hp:p>
</hs:sec>
```

### 자주 쓰는 블록

- **문단**: `<hp:p id=고유ID paraPrIDRef=문단스타일>` > `<hp:run charPrIDRef=글자스타일>` > `<hp:t>텍스트</hp:t>`
- **빈 줄**: run 안에 `<hp:t/>` (self-closing)
- **서식 혼합**: 한 문단에 run 여러 개, 각각 다른 `charPrIDRef` (예: 본문 0 + 볼드 7)
- **표**: `<hp:p>` > `<hp:run>` > `<hp:tbl rowCnt colCnt>` > `<hp:tr>` > `<hp:tc>` > `<hp:subList>` > `<hp:p>`. 셀마다 `cellAddr`(0-기준 좌표)·`cellSpan`·`cellSz`·`cellMargin` 필수. 전체 XML은 SKILL.md "표 작성법" 참조

### 수치 규칙 (HWPUNIT)

- 1pt = 100, 10pt 글자 = height 1000, 1mm ≈ 283.5
- A4 본문폭 = 42520 (용지 59528 − 좌우여백 8504×2). **표 열너비 합계는 반드시 42520**
- 행 높이 통상 2400~3600
- 문단 id는 `1000000001`부터 순차, 표 id는 별도 범위(예: `1000000099`~). 문서 내 중복 금지

### 들여쓰기·정렬은 공백이 아니라 paraPr로

공백 문자로 들여쓰기하지 않는다. header.xml의 paraPr left margin(예: report 템플릿 paraPr 24/25/26 = 600/1200/1800)을 참조한다.

## 4. header.xml 규칙 (스타일)

- 템플릿의 header.xml을 그대로 쓰는 것이 기본. 새 스타일이 필요하면 charPr/paraPr/borderFill을 **추가**하고 각 그룹의 `itemCnt`를 실제 자식 수와 일치시킨다 (`fix_namespaces.py`가 보정해 주지만 처음부터 맞추는 게 안전)
- section0.xml의 `charPrIDRef`/`paraPrIDRef`/`borderFillIDRef`는 header.xml에 정의된 ID여야 한다 (참조 정합성)
- paraPr에는 `hp:switch`(`hp:case`+`hp:default`) 구조 필수
- 폰트: fontRef `hangul="0"`=함초롬돋움, `"1"`=함초롬바탕 (base 기준)

## 5. 생성 후 검증 파이프라인 (순서 고정)

```bash
python "$SKILL/scripts/validate.py" result.hwpx                        # 1. 구조 검증
python "$SKILL/scripts/fix_namespaces.py" result.hwpx                  # 2. 네임스페이스·itemCnt 보정
python "$SKILL/scripts/finalize_hwpx.py" result.hwpx --strip-linesegarray  # 3. 줄배치 캐시 제거
python "$SKILL/scripts/validate.py" result.hwpx --layout               # 4. 레이아웃 위험 경고
# (레퍼런스가 있으면) page_guard.py / content_guard.py
python "$SKILL/scripts/gonmun_lint.py" --hwpx result.hwpx --format text  # 공문서라면 표기 검수
python "$SKILL/scripts/finalize_hwpx.py" result.hwpx --hancom          # 한컴 COM 실열림 (Windows+한글 환경)
```

`--hancom` 검사가 불가한 환경이면 **사람이 한글로 열어 확인하는 단계를 반드시 남긴다** — 스키마 통과 ≠ 한글에서 열림 보장.

## 6. 흔한 실패 지점 (전부 실제 사고 이력 있음)

1. **일반 ZIP 재압축** → mimetype 순서/압축 깨져 한글이 못 엶. 반드시 pack.py 또는 원시 엔트리 교체
2. **linesegarray 잔존** → 본문 수정 후 줄배치 캐시가 남으면 한컴이 손상/변조 경고. finalize로 제거
3. **pretty-print된 XML 재패키징** → 삽입된 공백·줄바꿈이 본문으로 렌더링
4. **네임스페이스 프리픽스 훼손** (`hp:`/`hs:`/`hh:`/`hc:` 유지 필수)
5. **ID 참조 불일치** — section이 header에 없는 charPr/paraPr를 참조
6. **표 열너비 합 ≠ 본문폭** → 레이아웃 붕괴
7. **`hp:t` 내부 자식 컨트롤(`hp:fwSpace`·`hp:lineBreak`) 삭제** → 손상 가능성. 텍스트를 비울 때도 태그는 유지
8. **secPr 누락** — 첫 문단 첫 run에 없으면 문서가 안 열리거나 용지 설정 소실
